2. r/devsecops post

Title: Static path analysis plus an isolated runtime contract for n8n AI
workflows

I maintain a small open source lab for checking n8n AI agent workflows
before production. It has three parts:

- a static scanner that follows paths through the exported JSON and
  reports things like untrusted input reaching a model, a model reaching
  an external action with no approval step, and HTTP URLs derived from
  workflow data
- an exposure graph that draws only the proven risky paths, with finding
  IDs on each edge and a ledger that maps IDs back to exact node paths
- a runtime regression gate that sends synthetic requests to an isolated
  staging copy and checks eight behaviors that must not change, such as
  rejecting unauthenticated requests and keeping injection markers behind
  approval

The repo ships an intentionally unsafe fixture (10/100, 9 findings) and a
hardened rebuild (93/100). I did not force the hardened one to 100: it
still derives an outbound URL from workflow data, so that path stays
visible for manual review. Everything runs locally, no workflow upload,
no AI API calls.

https://github.com/0xCD4/n8n-ai-agent-security-lab

I would be interested in redacted false positives and agent workflow
patterns that deserve another rule.

To validate the manual side I am doing three pilot reviews at EUR 99:
one redacted workflow, the five highest-risk paths traced by hand,
remediation notes and one retest.
